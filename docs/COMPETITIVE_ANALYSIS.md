# 竞品调研

> 调研现有视觉小说 / AVG 引擎，分析各自优劣势，明确 Natsume 的差异化定位。

## 1. Unity 生态

### Naninovel

- **定位**：Unity 上最成熟的商业 VN 引擎
- **价格**：$168（Asset Store），闭源
- **特点**：
  - 自定义脚本语言 `.nani`，语法简洁
  - 内置可视化编辑器、实时预览、热重载
  - 完善的存档/读档、Backlog、自动/快进
  - 支持 Live2D、Spine 集成
  - Addressables 资源管理
  - 活跃的社区和文档
- **不足**：
  - 闭源，深度定制困难
  - 脚本格式固定，无结构化数据层（不利于外部工具链集成）
  - 性能在大规模项目中有报告瓶颈
  - 对日式 Galgame 特有功能（差分立绘、角色语音独立控制等）支持不完整

### Fungus

- **定位**：免费开源的 Unity 叙事工具
- **价格**：免费（MIT）
- **特点**：
  - 可视化流程图编辑器（基于节点）
  - 入门门槛极低，适合非程序员
  - 社区较大（GitHub 1.5k+ stars）
- **不足**：
  - **已停止维护**（最后更新 2021 年左右）
  - 架构老旧，扩展性差
  - 不支持 async/await，依赖协程
  - 无存档系统、无 Backlog、无语音系统
  - 不适合商业级 Galgame 开发

### Nova

- **定位**：开源 Unity VN 框架
- **价格**：免费（MIT）
- **特点**：
  - Lua 脚本驱动
  - 支持热重载
  - 代码质量较高
- **不足**：
  - 社区较小，文档不完善
  - 功能覆盖度不如 Naninovel
  - Lua 学习曲线对编剧不友好

## 2. 非 Unity 引擎

### Ren'Py

- **定位**：全球最流行的开源 VN 引擎
- **价格**：免费（MIT）
- **特点**：
  - Python 基础 + 自定义脚本语言
  - 跨平台（Windows/Mac/Linux/Android/iOS/Web）
  - 巨大的社区（Steam 上大量 Ren'Py 游戏）
  - 完善的存档、Backlog、设置系统
  - 丰富的转场效果和动画
- **不足**：
  - 非 Unity 生态，无法利用 Unity 的渲染能力和工具链
  - Python 性能限制，复杂演出效果受限
  - UI 定制需要较深的框架知识
  - 对差分立绘、语音驱动表情等日式 Galgame 高级功能缺乏原生支持

### KiriKiri / KAG（吉里吉里）

- **定位**：日本传统 Galgame 引擎
- **价格**：免费（开源）
- **特点**：
  - 日本商业 Galgame 的事实标准（大量商业作品使用）
  - 对日式 AVG 功能支持最完整
  - 脚本语法成熟（KAG 标签语法）
- **不足**：
  - 仅支持 Windows
  - 技术栈老旧（TJS 脚本语言）
  - 不再活跃开发
  - 无法利用现代引擎的 3D、粒子、Shader 能力

### Ink / Inkle

- **定位**：叙事脚本语言 + 运行时
- **价格**：免费（MIT）
- **特点**：
  - 专注叙事逻辑和分支结构
  - 强大的分支/条件/变量系统
  - 可嵌入 Unity（ink-unity-integration）
  - Inky 编辑器
- **不足**：
  - 仅是叙事层，不包含表现层（对话框、立绘、音频等需要自己实现）
  - 不是完整的 VN 引擎
  - 对 AVG 演出指令没有原生概念

## 3. 商业日式引擎 vs 开源方案的差距

调研日本商业 Galgame 工作室常用的引擎功能，开源方案普遍缺失：

| 功能 | 商业引擎 | 开源方案现状 |
|------|----------|-------------|
| 差分立绘合成（Body + Face） | 标配 | 大多不支持或需手动实现 |
| 角色独立语音音量控制 | 柚子社等标配 | 几乎没有 |
| 语音驱动表情切换 | 部分高端作品 | 无 |
| 语音收藏 & 场景跳转 | 部分作品 | 无 |
| 精细文字速度控制（逐字间隔、标点停顿） | 标配 | 粗粒度 |
| 快进仅已读 / 未读确认 | 标配 | 部分支持 |
| 多样化选项呈现（地图、角色选择等） | 常见 | 仅文字选项 |

## 4. 开发者常见痛点

基于社区讨论和开发者反馈整理：

1. **架构耦合**：多数开源方案核心逻辑与 Unity 深度耦合，难以单元测试
2. **扩展性差**：添加自定义指令需要修改框架源码，而非注册式扩展
3. **存档系统脆弱**：改脚本后存档失效，缺乏版本兼容机制
4. **编辑器缺失**：程序员可以写脚本，但编剧和策划无法参与
5. **日式功能缺失**：差分立绘、角色语音控制等日式 Galgame 核心功能在开源方案中几乎为空白

## 5. Natsume 的差异化定位

基于竞品分析，Natsume 的核心竞争力：

| 维度 | Natsume 策略 | 对标竞品 |
|------|-------------|---------|
| **架构** | 四层分离，Core 纯 C# 可独立测试 | 优于 Fungus/Nova 的耦合架构 |
| **脚本** | YAML(IR) + DSL 双层，编辑器/编剧各得其所 | 优于 Naninovel 的单一格式 |
| **扩展性** | 命令模式 + 注册式扩展，无需改框架源码 | 对标 Naninovel，优于其他开源 |
| **日式功能** | 差分合成、语音驱动表情、角色音量、语音收藏 | 填补开源空白，对标 KiriKiri 功能深度 |
| **设置系统** | 精细粒度控制（逐字间隔、标点停顿） | 超越所有开源方案 |
| **选项系统** | 抽象 IChoicePresenter，支持任意呈现方式 | 独特设计 |
| **编辑器** | 节点图 + 属性面板 + 实时预览 + 场景跳转 | 对标 Naninovel 编辑器 |
| **开源** | MIT，代码质量高，文档完善 | 填补 Unity 生态高质量开源 VN 框架空白 |

**一句话定位**：Natsume 是 Unity 生态中第一个同时具备**商业日式 Galgame 功能深度**和**现代软件架构质量**的开源 AVG 框架。
